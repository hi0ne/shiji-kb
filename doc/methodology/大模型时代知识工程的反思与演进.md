# 大模型时代（LLM-Native）数字人文与知识工程的反思与演进

> 本文探讨在百万 Token 超长上下文与 Multi-Agent 时代，传统的“抽取-结构化-组装”流水线是否过时，以及面向未来的下一代研究范式。

---

## 一、当前 9 阶段流水线的“过渡期”特征

目前《史记》项目采用的框架（定本 -> 实体标注 -> 事件抽取 -> 图谱构建 -> SKU封装），本质上是 **“传统知识工程（符号主义） + LLM 赋能”** 的产物。
在当前的 LLM 前沿视角下，这种方式确实暴露出一些“传统”的笨重感：

1. **Schema 过度刚性**：预定义 18 类实体和 11 类事件，导致模型为了迎合格式而消耗算力。历史的复杂性有时无法被简单的三元组（SPO）囊括。
2. **碎片化与信息损耗**：把长文切碎成一段段，单独抽取结构，再强行拼装，会丢失长距离上下文的隐式逻辑和叙事张力。
3. **静态知识单元（SKU）的局限**：人工预先设计出 434 种知识卡片，这种遍历式的“静态编译”思维没有发挥 LLM 动态生成和跨域关联的优势。

---

## 二、当前更先进的四大原生范式（LLM-Native Paradigms）

在大模型前沿研究中，知识库的构建和利用正在向以下四种范式演进：

### 1. GraphRAG（微软架构：无模式全局知识聚合）
- **传统方式**：定义 Schema -> 抽取节点 -> 固化图谱（当前做法）。
- **先进方式**：使用 OpenIE（开放信息抽取），LLM 自动发现文本中的实体和事件并聚类为“社区（Communities）”，逐层自下而上地生成全局摘要。
- **优势**：无需预先定义什么是“事件”或“实体类别”，模型能自动发现诸如“关东诸侯对秦的抵触心理演变”这种在传统实体抽取中会漏掉的非结构化现象。

### 2. Long-Context 原生推理（超视距跨章分析）
- **传统方式**：各章单独切分处理 -> 最后合并推断。
- **先进方式**：利用 Gemini 1.5 Pro（原生 2M token）或 Claude 3.5（200K token），直接将整部《史记》或几十万字原文抛入内存。
- **优势**：直接提问“比对《项羽本纪》与《高祖本纪》中关于鸿门宴的叙述分歧”，模型可以原生完成细粒度的交叉验证，而不必经过“图谱三元组”这一中间介质。

### 3. Multi-Agent 辩论与考据体系
- **传统方式**：通过一段固定的 Python lint 脚本或单一的反思 prompt 进行年代审查。
- **先进方式**：设置不同人设的 Agent 协作网络。例如：
  - `文献发掘者 (Retriever)`
  - `逻辑推理者 (Chronologist)`
  - `恶魔辩护士 (Skeptic)` 专门寻找年代冲突和史料矛盾
- **优势**：动态解决冲突。对于生卒年不详等模糊地带，不再强行输出一个推断值，而是给出一份完整的“考据辩论报告”。

### 4. 工具调用与神经符号协同（Neuro-Symbolic Reasoning）
- **传统方式**：把图谱打包成 JSON，写死前端交互展现（如应用层的地铁图、知识卡片）。
- **先进方式**：大模型作为大脑，图谱作为工具（Tool）。用户提问时，Agent 自动编写 Cypher 语句查询底层的 RDF/Neo4j 图谱，结合查出的时空参数临时绘制地铁图。

## 三、但为什么当前的《史记》框架不仅没有“被淘汰”，反而不可替代？

尽管上面的新兴范式非常惊艳，但针对**数字人文（Digital Humanities）和严肃史料考据**，当前这套“略显古板”的流水线不仅没有过时，反而弥补了纯大模型方案的致命缺陷：

1. **大模型的“幻觉”无法根除，而史学要求 100% 的字际溯源（Grounding）。**
   - 纯大模型范式能告诉你“韩信在某年去了哪里”，但很难让你精确看到在《史记》哪一卷的哪一句的哪几个字。这套管线通过 `〖@韩信〗` 和 Purple Numbers 锚点，将知识物理绑定到了经纬度级别的像素上，这是严肃研究的底线。

2. **渲染与视觉辅助仍然依赖强结构。**
   - 人类依然需要排版精美的页面。LLM 直接生成的文本不具备多色高亮、悬浮卡片、以及互动式的 HTML 页面。当前流水线提供的“渲染交付层”依然具有刚需性。

3. **研究过程的“可重复性”与“透明性”。**
   - 纯 Agent 推理一个历史结论，是一个黑盒（每次运行结果可能不同）。当前的流水线能够吐出结构化的 `.tsv` 和 `.json`，让历史学家可以审查批改，形成闭环。

## 四、下一代《史记》知识库的演进蓝图

综合来看，未来的知识库不需要抛弃现有成果，而是走向 **“底层刚性，上层柔性”的 Neuro-Symbolic 架构**：

- **L1/L2 结构保留（底座）**：保留定本、目录段落编号（Anchor）和基础实体标注。不指望用大模型代替高亮，依然生成 HTML 页面。
- **L3 知识层升级（核心改进）**：放宽 11 类事件的限制，引入局部 GraphRAG 聚类，使用大模型在 Anchor 级别总结“群落知识”，不要死磕每个事件的年代对齐。
- **L4/L5 应用层颠覆（柔性化）**：
  - **废弃静态 SKU**：不再把“韩信传记”或者“军事策略”预先打包为 434 个 Markdown 文件。
  - **引入 MCP Agent**：基于现在的结构化索引（Entities, Chapter IDs, Anchor IDs），开发一组 Tool 接口。
  - 当用户提问时，利用大模型的 Agent 动态检索锚点，现场合成一版比静态 SKU 更切题的报告。

**结论**：这个项目在知识**表达和存储**层面非常扎实，绝不过时；它显得过时的地方在于知识的**生产调度和最终分发**过于手工化。未来的迭代方向，就是用 Agent 体系把现在那一套 Python 批量查错与打包脚本，重构为具备自主规划认知能力的考据机器网络。
