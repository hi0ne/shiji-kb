# 系统设计文档

> 本目录用于描述《史记》知识库的系统架构设计，回答“为什么这样分层、各层职责是什么、哪些能力已经存在、哪些能力需要新增”这类问题。

---

## 一、目录定位

本目录属于**架构层**文档，不直接描述脚本命令、开发流程或单步操作细节。

推荐将仓库文档分为四层：

- `doc/architecture/`：系统如何分层、模块如何协作、边界在哪里。
- `doc/methodology/`：方法论、通用框架、研究视角。
- `doc/spec/`：格式规范、标注规则、字段定义。
- `doc/workflow/`：执行流程、发布步骤、操作说明。

`skills/` 则处于更偏执行的工序层，回答“某一步具体怎么做”。

## 四、当前架构结论

基于现有仓库实现，系统已经具备：

- 结构化文本底座
- 实体标注、实体索引与章节级消歧
- 事件、关系、本体与推理的主干工序
- 独立的 `ontology/` 知识单元装配结果

但 `ontology/` 当前更像**已生成的知识资产 + 局部后处理脚本**，还没有完全纳入主干流水线。因此本目录的核心任务，是把这部分纳入正式架构设计，而不是另起一套平行框架。
