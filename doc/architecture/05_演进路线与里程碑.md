# 演进路线与里程碑

> 本文定义《史记》知识库从现有九阶段框架走向“静态严谨底座 + 动态输出层”的实施顺序。本文只定义阶段，不进入开发实现。

---

## 一、阶段目标

系统演进分为四步：

1. 固化底座
2. 正式纳入 ontology 装配层
3. 建立统一检索与路由层
4. 接入动态输出与多步编排

---

## 二、里程碑定义

### M1 底座清晰化

目标：

- 明确 L1-L3 边界
- 确认实体、事件、关系、本体输出契约
- 明确现有脚本与产物的主从关系

验收标准：

- 能用一张映射表说明 `chapter_md/`、`kg/`、`ontology/` 的上下游关系

### M2 ontology 装配纳管

目标：

- 把 ontology 从结果目录提升为正式装配层
- 明确 factual / procedural / relational 的输入输出契约
- 定义 dedup / bucketing / confidence 的治理位置

验收标准：

- 每类 SKU 都有来源说明
- 装配层与实体层的关系被明确文档化

### M3 检索与路由统一

目标：

- 定义运行时检索资产
- 建立问题类型到索引类型的路由矩阵
- 明确 LlamaIndex / GraphRAG / LangGraph 的引入时机

验收标准：

- 至少能区分局部事实问答、关系问答、综述问答三类路径

### M4 动态输出落地

目标：

- 动态问答、人物卡片、时间线、关系摘要
- 每条输出都能回证据
- 冲突时支持降级或复核

验收标准：

- 输出层不再依赖手工静态页面作为唯一入口
- 高置信输出都带来源锚点

---

## 三、推荐顺序

### 现在先做

1. 架构文档
2. ontology 装配层定义
3. 数据契约与质量规则

### 后续再做

1. 统一查询接口
2. GraphRAG 级全局摘要
3. LangGraph 编排层

### 暂不建议现在做

1. 完全重写九阶段工序
2. 让动态输出绕过静态知识层
3. 一开始就上全量多智能体复杂编排

---

## 四、对现有框架的判断

现有框架的状态可以概括为：

- L1-L3 已经非常扎实
- L4 已有结果但未完全制度化
- L5 方向明确但尚未正式架构化

因此后续工作重点不是“重建一套新系统”，而是：

**把已存在的知识资产与脚本成果，提升为可解释、可复用、可扩展的正式架构。**

---

## 五、阶段性风险

1. 如果跳过 ontology 装配层直接做动态问答，系统会失去高层知识入口。
2. 如果跳过证据治理直接做 Agent 编排，系统会变成不可复核的黑盒。
3. 如果重复建设一套实体层，会造成规范名和别名体系分裂。

因此推荐路线是：

**保留现有实体层，补齐 ontology 装配层，再建设运行时路由层。**
