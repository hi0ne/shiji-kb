# 系统整体架构

> 本文定义《史记》知识库的系统分层、数据流、模块边界，以及“静态严谨层 + 动态输出层”的总体方案。

---

## 一、设计目标

系统设计遵循三个优先级：

1. **严谨性优先**：任何高置信结论都必须能回指原文锚点。
2. **结构与生成分离**：底层知识资产稳定，顶层输出按问题动态组织。
3. **渐进式演进**：优先复用现有九阶段框架，再补齐 ontology 装配与运行时路由能力。

---

## 二、五层架构

```text
L1 源文本层
    archive/ docs/original_text/

L2 结构化文本层
    chapter_md/ tables/

L3 知识构建层
    kg/entities/ kg/events/ kg/relations/ kg/rdf/

L4 知识装配层
    ontology/skus/ ontology/*.md

L5 运行时检索与动态输出层
    MCP / 检索路由 / 应用生成 / 问答
```

### L1 源文本层

职责：

- 保存原始语料与定本。
- 作为所有下游工序的最终核验基线。

对应目录：

- `archive/`
- `docs/original_text/`

### L2 结构化文本层

职责：

- 将连续文本切分为可引用单元。
- 建立段落编号、标题结构、区块边界、注释层。

对应目录：

- `chapter_md/`
- `tables/`

### L3 知识构建层

职责：

- 抽取实体、事件、关系、本体与推理结果。
- 形成稳定的中间知识资产，而不是直接输出给最终用户。

对应目录：

- `kg/entities/`
- `kg/events/`
- `kg/relations/`
- `kg/rdf/`

### L4 知识装配层

职责：

- 将中间知识资产封装为可复用知识单元。
- 区分 factual、procedural、relational 三类资产。
- 生成索引、映射、聚类、去重和后处理结果。

对应目录：

- `ontology/`
- `ontology/skus/`

### L5 运行时检索与动态输出层

职责：

- 根据问题类型选择检索路径。
- 组合静态资产，生成动态回答、时间线、关系图、人物卡片等输出。

对应目录与接口：

- `app/`
- `docs/`
- `mcp_server`

## 三、与现有九阶段的映射

| 现有阶段 | 当前职责 | 归属层 |
|----------|----------|--------|
| 01 校勘 | 定本、校验文本基线 | L1 |
| 02 结构分析 | 段落、区块、编号、结构语义 | L2 |
| 03 实体构建 | 标注、索引、别名、消歧 | L3 |
| 04 事件构建 | 事件识别、纪年 | L3 |
| 05 关系构建 | 关系图、事实三元组 | L3 |
| 06 本体构建 | taxonomy、RDF/OWL | L3 |
| 07 逻辑推理 | 审查、补全、冲突检测 | L3 |
| 08 SKU构造 | 知识单元封装 | L4 |
| 09 应用构造 | 阅读器、问答、时间线等 | L5 |

关键结论：

- `ontology/` 不是与 `kg/` 平行竞争的体系，而是 `kg/` 的**装配层**。
- 运行时问答与动态输出不应该跳过 `kg/` 和 `ontology/`，直接对原文做无约束生成。

---

## 四、静态严谨层与动态输出层的边界

### 静态严谨层

包含 L1 到 L4，特征是：

- 可审查
- 可复现
- 可版本化
- 可追溯到锚点

### 动态输出层

包含 L5，特征是：

- 按问题生成
- 按受众调整粒度
- 允许多索引组合检索
- 不直接产生新的基础事实

设计铁律：

**动态输出可以重组知识，但不能篡改静态知识底座。**

---

## 五、当前缺口

现有主干框架已经覆盖 L1、L2、L3 的大部分内容，也有 L4 的结果资产，但仍存在三个缺口：

1. `ontology/` 尚未完全纳入主干流程定义，仍偏结果目录。
2. `SKU构造` 在方法论里有位置，但工程化生成链路尚不完整。
3. 运行时检索与路由方案还未形成正式架构文档。

因此本轮系统设计的任务不是重写九阶段，而是**补齐 L4 与 L5 的架构定义**。
