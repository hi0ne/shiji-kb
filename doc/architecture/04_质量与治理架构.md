# 质量与治理架构

> 本文定义从实体标注到 ontology 装配，再到运行时动态输出的质量约束、治理原则和人工复核机制。

---

## 一、质量目标

系统质量不以“答案像不像”衡量，而以三项指标衡量：

1. **可追溯**：答案是否能回指原文锚点。
2. **可一致**：实体名、事件名、关系类型是否前后一致。
3. **可治理**：错误能否定位、修正、回放和再验证。

---

## 二、分层质量约束

### L1-L2 文本层

要求：

- 去除标记后文本与原文逐字一致
- 段落编号稳定
- 标题与区块边界可复现

### L3 知识层

要求：

- canonical name 唯一
- 别名可回溯到规范名
- 事件 ID 连续且可定位
- 关系谓词受控

### L4 ontology 装配层

要求：

- SKU 必有来源 chunk 或来源锚点
- factual / procedural / relational 分类稳定
- 不重复打包同一知识点而不加说明
- 打包结果必须可被主索引引用

### L5 动态输出层

要求：

- 高置信回答必须附证据
- 低置信回答必须显式降级
- 出现冲突时优先呈现分歧而非强行统一

---

## 三、治理对象

重点治理五类对象：

1. 实体
2. 事件
3. 关系
4. SKU
5. 运行时答案

每类对象都应具备：

- 稳定 ID
- 来源锚点
- 最近更新时间
- 质量状态

---

## 四、ontology 的治理重点

当前 `ontology/` 已经出现了三类治理需求：

### 1. 去重治理

不同 SKU 可能讨论同一主题但视角不同，因此治理目标不是“机械去重”，而是：

- 判定是否重复
- 若不重复，说明差异用途
- 若重复，决定保留 / 合并 / 重写

### 2. 分桶治理

分桶的意义不只是压缩，而是为后续检索和上下文组装做准备。

### 3. 置信度治理

当前许多 ontology 产物中 `confidence` 为空。后续必须定义：

- 来源单一且证据清晰 = 高
- 多源拼装但无冲突 = 中
- 需要推断或存在歧义 = 低

---

## 五、人工复核入口

以下情况必须支持人工介入：

1. 同名异人高歧义
2. 事件年代冲突
3. ontology 去重结果不确定
4. procedural 提炼存在明显抽象失真
5. 运行时答案无法形成稳定证据链

人工复核不是补锅，而是主系统的一部分。

---

## 六、治理闭环

```text
抽取
→ 校验
→ 装配
→ 去重/分桶
→ 检索使用
→ 发现冲突
→ 回写规则与修正
```

这个闭环必须存在于实体层、ontology 层和运行时层三个位置。
